# 📊 Аналіз бізнес-моделі маркетплейсу Olist

---

## 🏢 Про проєкт

Цей проєкт базується на аналізі датасету **Olist Brazilian E-Commerce** — відкритих даних бразильського маркетплейсу.

Аналіз досліджує бізнес-модель Olist: звідки береться дохід, чи повертаються клієнти, та які фактори впливають на ці показники. Метою дослідження було визначити основні джерела доходу маркетплейсу, дізнатися більше про клієнтів, а також визначити вплив різних факторів, зокрема: швидкості доставки і оцінок відгуків на показники компанії 

Інсайти надаються за наступними ключовими напрямками:

- **Скільки клієнтів повертаються за повторними покупками, і як швидко вони "відпадають"**
- **Звідки насправді береться дохід** — з великої кількості дрібних замовлень чи з невеликої кількості дорогих**
- **Які типи клієнтів існують** та наскільки вони цінні для бізнесу
- **Що впливає (а що ні) на повторні покупки** — якість відгуків, швидкість доставки, характеристики товару

- ## 🗂 Структура даних

Датасет *Olist* містить кілька таблиць, зокрема:

- **orders** — основна таблиця датасету. Тут присутні: дата покупки, статус, очікувана та фактична дата доставки
- **customers** — клієнти: `customer_id` (унікальний на замовлення) та `customer_unique_id` (унікальний на людину), місто/штат
- **order_items** — товарні позиції: товар, продавець, ціна, вартість доставки
- **products** — товари: категорія, довжина назви/опису, кількість фото
- **order_payments** — платежі: тип оплати, кількість частин (installments), сума
- **order_reviews** — відгуки: оцінка (1-5), дата створення
- **sellers** — продавці: місто/штат
- **geolocation** — географічні координати за поштовим індексом

### Структура схем у базі даних

- **`public`** — сирі, необроблені таблиці, завантажені без змін.
- **`clean`** — представлення (views), побудовані поверх `public`, які використовуються в усьому аналізі:
  * `clean.active_orders` — виключає скасовані та недоступні замовлення
  * `clean.order_reviews` — очищена від дублікатів `review_id`
  * `clean.customer_first_purchase` — перша покупка кожного клієнта

Ключове рішення при очищенні: аналіз клієнтів проводиться за `customer_unique_id`, а не за `customer_id`, оскільки Olist присвоює новий `customer_id` кожному окремому замовленню — навіть для того самого покупця.
